# Project Boundaries, Overview & Knowledge Base

## 0. 🚨 HIGHEST PRIORITY: Разработка модов и папки `*_Port`

- **Рабочая область**: При создании собственных модов или портировании/модификации существующих модов вся разработка, редактирование и создание файлов производятся **ИСКЛЮЧИТЕЛЬНО** в папке, содержащей в имени маркер **`_Port`** (например, `<ModName>_Port`).
- **Неприкосновенность оригиналов**: Папка оригинального мода является **СТРОГО READ-ONLY**. Изменять, удалять или перезаписывать оригинальные файлы запрещено.
- **Workflow**: Анализируем оригинал -> переносим и собираем адаптированную версию только в `*_Port`.
- **Автономность приложения (Запрет ручной правки выходных данных)**: При разработке или улучшении модулей **категорически запрещено** вручную или вспомогательными скриптами исправлять файлы в директории игры/модов (`Zomboid/mods/...`) или результаты работы приложения. **Приложение обязано уметь делать всё само.** Задача разработчика — реализовать логику внутри кодовой базы PZ Management (`src/`), чтобы программа формировала корректный результат автономно.

## 3. Project Overview & Architecture

**PZ MANAGEMENT** — desktop-приложение (Electron + React 19 + TypeScript, Zero runtime dependencies) для работы с модами Project Zomboid (B41 / B42).

### Модули:
- **Stalker**: Обозреватель и инспектор установленных модов (Steam, Workshop, локальные, серверные).
- **Loadout**: Порядок загрузки клиента (`default.txt`) и серверов (`.ini`), сортировка зависимостей, профили.
- **Workbench**: Создание модов (scaffold), редактирование `mod.info`, валидация (Lua, скрипты, JSON/txt переводы, теги), упаковка в Workshop.
- **Ledger**: Парсинг краш-логов и консоли (`console.txt`), привязка ошибок к модам.
- **Tools**: FBX Forge (конвертер моделей, поддержка `.x` формата PZ) и интеграция с Notepad++.

## 4. 🤖 Обязательное использование MCP-сервера `pz-modding` (Автономный режим)

> [!IMPORTANT]
> **ПРАВИЛО БЕЗ НАПОМИНАНИЙ (Zero-Reminder Autonomous Policy)**:
> Агент **ОБЯЗАН** использовать инструменты MCP-сервера `pz-modding` (`call_mcp_tool`) проактивно и автоматически. Пользователь **не должен** напоминать об их использовании.
> При возникновении любой из описанных ниже ситуаций агент **немедленно** вызывает соответствующий инструмент MCP:

1. **`pz_decompile_class` (Инспекция Java-движка игры)**:
   - **Триггер**: Любые вопросы о методах, полях, сигнатурах движка или механиках Java (`IsoPlayer`, `IsoZombie`, `HandWeapon`, `SwipeStatePlayer`, `CombatManager`, `IsoGameCharacter` и др.).
   - **Запрет**: Не делать догадок о методах Java и не писать самодельные скрипты Java в scratch-папке.
   - **Вызов**: `pz_decompile_class` с `className` и `methodsOnly: true` (или `false` для полного декомпилятора).

2. **`pz_lookup_event` (События Lua)**:
   - **Триггер**: Всегда перед добавлением или изменением любого обработчика событий Lua (`Events.<EventName>.Add(...)`).
   - **Цель**: Проверить существование события и точные аргументы колбэка по официальному реестру 232 событий `LuaEventManager`.
   - **Вызов**: `pz_lookup_event` с параметром `name`.

3. **`pz_validate_item_script` (Скрипты предметов B42)**:
   - **Триггер**: После любого создания или изменения скриптов предметов/оружия/патронов (`media/scripts/*.txt`).
   - **Цель**: Проверка синтаксиса B42 (префиксы `base:weapon`, `base:normal`, соответствие фигурных скобок, обязательные свойства).
   - **Вызов**: `pz_validate_item_script` с параметром `filePath`.

4. **`pz_validate_sandbox_options` (Настройки песочницы)**:
   - **Триггер**: При создании или изменении `media/sandbox-options.txt`.
   - **Цель**: Проверка критического правила B42 `VERSION = 1,` (с обязательной завершающей запятой), валидация секций и проверка отсутствия BOM.
   - **Вызов**: `pz_validate_sandbox_options` с параметром `filePath`.

5. **`pz_audit_hygiene` (Аудит гигиены мода перед сдачей)**:
   - **Триггер**: Перед завершением работы над любым модом, перед синхронизацией и перед тестированием.
   - **Цель**: Автоматический аудит на скрытые критические ошибки PZ (UTF-8 BOM, кириллица вне `Translate/RU/`, устаревший `versionMax=` в `mod.info`).
   - **Вызов**: `pz_audit_hygiene` с `modDir`.

6. **`pz_sync_port_mod` (Развёртывание и синхронизация мода в игру)**:
   - **Триггер**: При необходимости скопировать или обновить собранный мод в рабочей директории игры `C:\Users\tamer\Zomboid\mods\<modId>`.
   - **Цель**: Безопасный перенос с предварительной гигиенической проверкой и жестким соблюдением правила исходника `*_Port`.
   - **Вызов**: `pz_sync_port_mod` с `sourceDir`, `modId`, `clean: true`.

## 5. 🎨 3D-Моделирование и интеграция с Blender MCP (`mcp-for-blender`)

- **Blender 5.2 LTS**: `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`
- **MCP Server**: `blender` в `~/.gemini/config/mcp_config.json` (инструмент `mcp-for-blender` через `uvx`).
- **Автономия**: Аддон активирован в `userpref.blend` с автозапуском сокета. Агент имеет право запускать Blender в фоновом режиме самостоятельно и использовать инструменты:
  - `execute_blender_code`: скриптинг `bpy` (геометрия, UV, риггинг под 34 кости `Master_Bones.xml`, перенос весов).
  - `get_scene_info` / `get_object_info`: проверка объектов, топологии и материалов.
  - `get_viewport_screenshot`: визуальный контроль модели во вьюпорте.
  - `export_scene`: экспорт в `.fbx` с правильными PZ осями и матрицами.
