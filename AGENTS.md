> [!CAUTION]
> ### 🚨 ПРАВИЛО НАИВЫСШЕГО ПРИОРИТЕТА: Разработка, портирование и папки `*_Port`
> При создании собственных модов или модификации/переделке/портировании существующих модов:
> 1. **Рабочая папка**: Вся разработка, создание новых файлов, модификации и адаптация кода ведутся **ИСКЛЮЧИТЕЛЬНО** в папке, содержащей в своём названии маркер **`_Port`** (например, `<ModName>_Port`).
> 2. **Неприкосновенность оригинала**: Папка оригинального мода является **СТРОГО НЕИЗМЕНЯЕМОЙ (READ-ONLY)**. Категорически запрещено изменять, перезаписывать или удалять исходные файлы оригинального мода.
> 3. **Рабочий процесс**: Оригинал используется только для чтения/анализа — вся чистая сборка, новые фичи B42 и изменения пишутся только внутри папки `*_Port`.

## 3. О проекте: PZ MANAGEMENT

**PZ MANAGEMENT** — это модульное десктопное приложение для управления, анализа, разработки и отладки модов игры **Project Zomboid** (поддержка сборок **Build 41** и **Build 42**).
- **Стек**: Electron, React 19, TypeScript, electron-vite.
- **Архитектурный принцип**: *Zero runtime dependencies* (минимализм во внешних зависимостях, максимальная автономность и безопасность при работе с файлами пользователя).

### Основные модули приложения:
1. **Stalker (Explorer)**: Автодетекция Steam / Workshop / папок игры. Парсинг `mod.info`, классификация модов по типам (карты, транспорт, оружие, сущности B42 и т.д.), проверка совместимости B41/B42, построение дерева зависимостей (`require=`), виртуализированный 3-панельный инспектор файлов.
2. **Loadout**: Управление порядком загрузки модов для клиента (`Zomboid/mods/default.txt`) и серверов (`Zomboid/Server/*.ini`). Интеллектуальная сортировка с учётом зависимостей (*Fix order*), поддержка карт (`media/maps`), привязка Workshop ID и профили.
3. **Workbench**: Инструменты автора модов — скаффолдинг структуры мода (B41/B42, `craftRecipe`, `PZAPI.ModOptions`), визуальный и текстовый редактор `mod.info`, статический валидатор (Lua-парсер с белым списком 217 событий, скрипты предметов/крафта, переводы B41/B42, теги Workshop), упаковка для Steam Workshop.
4. **Ledger**: Анализатор краш-логов и консольного вывода (`console.txt`, `Logs/*_DebugLog.txt`), свертывание стектрейсов, сопоставление ошибок с конкретными установленными модами (*Mod attribution*).
5. **Tools**:
   - **FBX Forge**: собственный конвертер 3D-моделей в `.fbx` (DirectX `.x` форматы игры, `.obj`, `.stl`, `.ply` и др. + опциональный fallback на `assimp`).
   - Мост с Notepad++ для подсветки синтаксиса скриптов PZ.

## 5. 🤖 Обязательное использование MCP-сервера `pz-modding` (Автономный режим)

> [!IMPORTANT]
> **ПРАВИЛО БЕЗ НАПОМИНАНИЙ (Zero-Reminder Autonomous Policy)**:
> Агент **ОБЯЗАН** использовать инструменты MCP-сервера `pz-modding` (`call_mcp_tool`) проактивно и автоматически. Пользователь **не должен** напоминать об их использовании.
> При возникновении любой из описанных ниже ситуаций агент **немедленно** вызывает соответствующий инструмент MCP.

### Спецификация применения инструментов:

1. **`pz_decompile_class` (Инспекция Java-движка игры)**:
   - **Когда вызывать**: При любых вопросах о методах, полях, сигнатурах движка или механиках Java (`IsoPlayer`, `IsoZombie`, `HandWeapon`, `SwipeStatePlayer`, `CombatManager`, `IsoGameCharacter` и др.).
   - **Запрещено**: Делать догадки о названиях методов Java или писать самодельные скрипты интроспекции Java в scratch-директории.
   - **Вызов**: `pz_decompile_class` с `className` (например, `zombie.characters.IsoPlayer`) и `methodsOnly: true` (или `false` для полного декомпилятора).

2. **`pz_lookup_event` (События Lua)**:
   - **Когда вызывать**: Всегда перед добавлением или изменением любого обработчика событий Lua (`Events.<EventName>.Add(...)`).
   - **Цель**: Проверить существование события и точные аргументы колбэка по официальному реестру 232 событий `LuaEventManager`.
   - **Вызов**: `pz_lookup_event` с параметром `name` (например, `OnWeaponHit` или `OnPlayerUpdate`).

3. **`pz_validate_item_script` (Скрипты предметов B42)**:
   - **Когда вызывать**: После любого создания или изменения скриптов предметов/оружия/патронов (`media/scripts/*.txt`).
   - **Цель**: Проверка синтаксиса B42 (префиксы `base:weapon`, `base:normal`, соответствие фигурных скобок, обязательные свойства).
   - **Вызов**: `pz_validate_item_script` с параметром `filePath`.

4. **`pz_validate_sandbox_options` (Настройки песочницы)**:
   - **Когда вызывать**: При создании или изменении `media/sandbox-options.txt`.
   - **Цель**: Проверка критического правила B42 `VERSION = 1,` (с обязательной завершающей запятой), валидация секций и проверка отсутствия BOM.
   - **Вызов**: `pz_validate_sandbox_options` с параметром `filePath`.

5. **`pz_audit_hygiene` (Аудит гигиены мода перед сдачей)**:
   - **Когда вызывать**: Перед завершением работы над любым модом, перед синхронизацией и перед тестированием.
   - **Цель**: Автоматический аудит на скрытые критические ошибки PZ:
     - Наличие UTF-8 BOM в файлах `.lua`, `.txt`, `.json` (ломает парсер игры).
     - Наличие кириллических символов за пределами папок `Translate/RU/`.
     - Наличие устаревшего тега `versionMax=` в `mod.info` (блокирует загрузку в B42).
   - **Вызов**: `pz_audit_hygiene` с `modDir`.

6. **`pz_sync_port_mod` (Развёртывание и синхронизация мода в игру)**:
   - **Когда вызывать**: При необходимости скопировать или обновить собранный мод в рабочей директории игры `C:\Users\tamer\Zomboid\mods\<modId>`.
   - **Цель**: Безопасный перенос с предварительной гигиенической проверкой и жестким соблюдением правила исходника `*_Port`.
   - **Вызов**: `pz_sync_port_mod` с `sourceDir`, `modId`, `clean: true`.

## 6. 🎨 3D-Моделирование и интеграция с Blender MCP (`mcp-for-blender`)

> [!NOTE]
> В систему интегрирован и подключен **Blender 5.2 LTS** через официальный MCP-мост (`mcp-for-blender`).
> Агент имеет право и возможность автономно создавать, редактировать, риггить и экспортировать 3D-модели для Project Zomboid.

### Конфигурация и окружение:
- **Blender 5.2 LTS**: `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`
- **Пакетный менеджер**: `C:\Users\tamer\.local\bin\uvx.exe` (входит в User PATH).
- **Конфигурация MCP**: `C:\Users\tamer\.gemini\config\mcp_config.json` (сервер `blender`).
- **Аддон**: `blender_mcp.py` установлен в `AppData/Roaming/Blender Foundation/Blender/5.2/scripts/addons/`, активирован в `userpref.blend` с `Auto-Start Server = True`.
- **Автономия запуска**: Агент может запускать Blender в фоновом режиме самостоятельно при необходимости выполнения 3D-задач.

### Набор доступных инструментов MCP Blender:
1. `execute_blender_code`: Выполнение Python-скриптов (`bpy`) внутри Blender (создание мешей, модификаторы, булевы операции, UV-развертка, привязка весов к 34 костям `Master_Bones.xml`).
2. `get_scene_info` / `get_object_info`: Инспекция иерархии объектов, мешей, материалов и полигонажа.
3. `get_viewport_screenshot`: Получение прямого снимка 3D-вьюпорта для визуального контроля формы, нормалей и топологии.
4. `export_scene`: Экспорт готовых моделей в формат `.fbx` (с соблюдением ориентации осей PZ, масштаба и запеканием трансформаций).
5. Генераторы ассетов и библиотеки: `search_sketchfab_models`, `search_polypizza_models`, `search_polyhaven_assets`, `generate_hunyuan3d_model`, `generate_hyper3d_model_via_text`.
